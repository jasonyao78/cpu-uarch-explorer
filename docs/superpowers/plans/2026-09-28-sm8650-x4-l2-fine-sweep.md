# SM8650 X4 fine-grained private-L2 sweep (P1) plan

> **Execution mode:** continue on `codex/sm8650-l2-pmu-calibration`, worktree
> `.worktrees/sm8650-l2-pmu-calibration`. No probe/runner code changes: the
> deployed digest-anchored `ptr_chase` and the P0-verified 6-event set are
> reused as-is. Run the device matrix only from a clean commit.

**Goal:** adjudicate the two unresolved private-L2 features left by the
2026-09-27 calibration: (a) image the 512→640 KiB L1 hit-rate collapse
directly with dense `l1d` events, and (b) locate the `l2d_cache_refill`
onset interval in the ~1–1.4 MiB region, the only surviving capacity signal.

**Architecture:** identical loop/environment semantics as the accepted
calibration and the P0 positive control (CPU7 taskset, controlled-baseline
governor transaction, 16,777,216 timed loads, 2 full-ring warmup passes,
10 fresh processes per case, explicit base pages with per-sample smaps
audit). Event set = the P0-verified 6-event cache group (`cycles 0x11`,
`l1d_cache_refill 0x03`, `l1d_cache 0x04`, `l2d_cache 0x16`,
`l2d_cache_refill 0x17`, `l3d_cache_refill 0x2a`) — exactly the X4's
6-programmable-counter budget, already proven non-multiplexed on this PMU.
`dtlb_walk` is excluded: it was verified near-zero throughout this size
range (≤0.02/1k) and would exceed the counter budget; a paired TLB run is
the documented contingency if anomalies appear.

**Why this sequence:** the P0 positive control
(`docs/reviews/2026-09-28-sm8650-pmu-positive-control.md`) established that
the refill **onset edge** retains capacity-discriminating power while
absolute magnitudes are prefetch-filtered. This sweep densifies exactly the
two onset regions; no outer-cache sizes are touched (handoff boundary).

## Acceptance rules

1. Same measurement-integrity gates as P0: 10 fresh processes per case,
   actual backing `base` per sample, `time_running == time_enabled` for
   every event/sample, environment pre/post gates valid, governor restored,
   thermal cutoff respected.
2. Anchor consistency: sizes shared with the calibration (512, 1024, 1152,
   1280 KiB) must reproduce its latency/cycles within run-to-run drift
   (≈ a few %); a systematic break invalidates cross-run comparison and
   triggers drift investigation before adjudication.
3. Feature (a) — L1 collapse: adjudicated from the dense `l1d_cache_refill`
   / `l1d_cache` curves across 448–800 KiB. The expected signature is an
   L1-miss-rate transition with `l2d_cache_refill` remaining at its
   near-zero floor — confirming the calibration's 512→640 KiB step as an
   L1 replacement artifact, not L2 capacity.
4. Feature (b) — refill onset: the onset interval is the first size range
   where `l2d_cache_refill` medians rise sustainedly above the floor
   (≈0.2–0.8/1k) across ≥2 adjacent sizes with IQR separation from the
   floor cohort. The onset **upper-bounds** the effective private-L2
   capacity (prefetch can only delay the onset, never advance it);
   latency/cycles coupling at the same sizes is required supporting
   evidence. Absolute refill magnitudes are never converted to miss rates
   (P0 rule).
5. Verdict grades: a capacity figure is promoted to the platform baseline
   only as an observed onset interval with explicit associativity/coloring/
   prefetch residuals; otherwise the question remains `OPEN/INCONCLUSIVE`.
