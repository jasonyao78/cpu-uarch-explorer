# SM8650 X4 细粒度私有 L2 扫描裁定

**⚠️ 复审更正（2026-09-28，外部评审，优先级 P0/P1）**

本文数据（§3 全部表格、§2 完整性核验）仍然有效；以下**裁定级内容被
驳回**，X4 私有 L2 门禁重新打开，外层 L3/LLCC 维持封锁：

1. **裁定 1（"L1 置换共振崩塌，CONFIRMED"）撤回，降级为候选假设之
   一。** 评审用官方 demand/prefetch 专用事件的两点 smoke（Awake/walt，
   仅诊断用）显示：512→640 KiB 的主变量是 **L1 硬件预取覆盖率约
   67%→3.9% 的崩塌**（demand L1 miss 33.0%→96.1%，demand L2 miss
   0.04%→0.22%）。这直接推翻"已确认是置换共振"的排他性表述；且本文
   用作旁证的 l1acc 超额依赖的"预取查找"解释与 `L1D_CACHE` 官方定义
   （排除 prefetches）矛盾。512→640 KiB 的当前稳妥表述：**硬件预取
   覆盖率崩塌的强证据**，正式裁定待 P0′ 复测。
2. **裁定 2（"起始沿区间 [768, 1216) KiB"）撤回。** 与逐样本数据矛
   盾：576 KiB 有 2/10 样本 ≈8.6/1k、608 KiB 1/10 ≈10.6/1k、640 KiB
   3/10 ≈10.3–12.2/1k，而 672/704/736/800 KiB 又大多回落——是从约
   576 KiB 起出现的**离散双态**，非单调起始沿；1216 KiB 仍含低态
   （2.91/1k）。且"≥1216 KiB 两个独立 run"表述错误：1216/1344/1408
   KiB 仅本单 run，≥1280 KiB 才有双 run 覆盖。
3. **裁定 3（"2 MiB 否决、1 MiB 最一致"）撤回。** 几何论证三处错误：
   (a) Cortex-X4 L2 为 **8 路**（非"最不利 4 路"）；(b) X4 L2 可选
   **512 KiB / 1 MiB / 2 MiB** 三档（非两档）；(c) 1.4 MiB 对 2 MiB
   4 路应为 ~2.8 行/组（非 1.75）。Arm TRM 另记 X4 L2 为 PIPT + 动态
   偏置替换，4 KiB 匿名页 PFN 着色可在名义容量未满前制造冲突 refill
   ——评审的 2 MiB/8 路随机组占用模型在 1.4 MiB 预期 ~3.7% 冲突溢出，
   与其 smoke 在 1408 KiB 实测 ~3.6% demand L2 miss **相容**。且
   SM8650 上游 DTS 补丁（Qualcomm 维护者 review）记 CPU7 L2 =
   `2097152` 字节（[补丁](https://lists.openwall.net/linux-kernel/2026/06/15/1727)），
   虽非硅上寄存器终证，但强于本文的曲线排除法。**2 MiB 未被否决，
   仍是外部证据最强的名义配置；1 MiB 保留为待检假设，不得称"最一致
   解释"。**
4. **§4 规则 2/3/4 的 PASS/CONFIRMED 裁定随之失效**（规则 1 测量完
   整性 PASS 保留）。§5 residuals 中"起始沿=有效容量上界"的推导同
   样依赖被驳回的单调度假设，一并撤销。
5. **保留有效的方法学警示**：448–480 KiB 低延迟+低 l1ref 的"幻影高
   原"现象真实存在（纯延迟曲线会误报），但其机制（预取 vs 置换）未
   定，作为 P0′ 的判别目标而非结论。

## 1. 裁定

1. **512→640 KiB 跳变 = L1 置换共振崩塌，与 L2 容量无关（CONFIRMED，
   高置信）。** 致密 l1ref 成像显示 L1 miss 率从 448 KiB 的 7.1% 平滑爬升
   经 512 KiB 的 25.1%、544 KiB 的 54.2% 到 640 KiB 的 91.6%，≥960 KiB
   饱和 ≈100%；同一区间 l2ref 全程钉在地板（0.24–0.79/1k）。所谓"512 KiB
   结构性延迟台阶"实为循环引用序列在伪 LRU 上的共振高原（448–480 KiB
   仍有 ~93% L1 命中）随 N/ways 比崩塌的过程——**这不是任何一级 cache
   的物理边界**。
2. **l2ref 起始沿区间 = [768, 1216) KiB（MODERATE-HIGH 置信）。** ≤736
   KiB 全部进程处于地板（≤0.44/1k，IQR 不重叠）；768–1152 KiB 出现
   布局依赖的双态 refill（逐进程从地板到 ~10–23/1k 不等，跨 run 同尺寸
   中位数可差 3–11×）；≥1216 KiB 两个独立 run 均为持续高位
   （17.4–21.9/1k）。
3. **名义 2 MiB 私有 L2 被实测否决（MODERATE-HIGH 置信）；名义 1 MiB
   为最一致解释（未证死）。** 任何 2 MiB 几何都能容纳 ≤1.4 MiB 工作集
   （最不利的 2 MiB 4-way 也有 1.75 行/组对 4 路），不可能在 1216–1408
   KiB 产生跨两个 run 的持续强制 refill；1 MiB 几何在 896–1408 KiB 区间
   的组冲突压力与观测完全吻合（§4.2）。按 P1 验收规则 5，晋升到平台
   认知的是**起始沿区间 [768, 1216) KiB** 这个观测事实，附带着色/相
   联度残差；"名义 1 MiB"保持 most-consistent hypothesis 等级。
4. **延迟耦合定量闭合。** 640→1408 KiB 的延迟缓升（12.17→15.43 cyc）
   由 refill 比例解释：+3.3 cyc ≈ 2%/load 的 refill × ~150 cyc 外层
   代价。起始沿之后没有第二级延迟悬崖——本扫描区间内不存在其他结构。
5. 方法学警示：**纯延迟曲线会把 448–480 KiB 的共振高原误报为 ~448
   KiB 的"快 cache"**（lmbench 类已知假象，本次被 PMU 直接成像）。仓
   库的耦合证据门禁（延迟+refill 联合）因此被保留为硬性规则。

## 4. 逐条验收规则裁定

1. **测量完整性：PASS。** 见 §2。
2. **锚点一致性：PASS（带观察）。** 512/1280 KiB 几乎逐值吻合；
   1024/1152 KiB 的 lat/cyc 在 ±3.7% 内；这两个尺寸的 l2ref 跨 run 散
   布（0.99 vs 11.56；15.0 vs 4.50）不是漂移，而是起始沿区内逐进程
   物理页布局（着色）双态的直接证据——IQR 在单 run 内即横跨地板与
   高位（如 768 KiB [0.65, 10.66]）。
3. **特征 (a) L1 崩塌：CONFIRMED。** l1ref 致密曲线（71→251→542→916
   →饱和 ~1001/1k）与延迟曲线逐点互洽（lat ≈ 命中率的加权平均），
   l2ref 全程地板。校准的"512→640 KiB 台阶"获得最终机制裁定：伪
   LRU 共振高原的崩塌段，非容量边界。l1acc 在高原区升至 ~1.9/1k（预
   取查找假设，SPECULATIVE），崩塌后回落 ~1.01/1k，方向自洽。
4. **特征 (b) 起始沿：区间裁定成立。** ≤736 KiB 全进程地板；768–1152
   KiB 双态（布局依赖）；≥1216 KiB 持续高位。上界推导：起始沿只能被
   预取**推迟**不能被提前，故有效私有 L2 ≤ 起始沿区；任何 2 MiB 几何
   与 ≥1216 KiB 的持续 refill 不兼容（§1.3）。1 MiB 名义 + 4 KiB 页
   着色/相联度冲突 = 最一致解释。**绝对 refill 幅度不作换算**（P0
   规则）。
5. **裁定分级：PASS。** 晋升为平台认知的是观测事实"有效起始沿区间
   [768, 1216) KiB + 2 MiB 名义被否决"；确切名义值保持
   most-consistent hypothesis；associativity/着色/预取残差显式在册。

## 5. 剩余不确定性（residuals）

1. L2 相联度/置换策略未直接测定；1 MiB 名义值依赖"X4 只有 1/2 MiB
   两种配置"的架构前提 + 几何排除法。
2. 4 KiB 页着色：10 次新进程展示了双态幅度，但未穷举着色彩空间；
   THP（2 MiB 页）下的起始沿形态未测（本扫描仅 base pages）。
3. 预取对起始沿的推迟量未知：起始沿是有效容量的**上界**，真实物理
   容量可能略小于区间下界。
4. 448–480 KiB 共振高原未做置换策略仿真；l1acc 高原区超额的预取查
   找假设未单独证实。
5. uncore/DSU 频率未锁定；外层延迟 ~150 cyc 为估计值（DERIVED）。
6. 1152 KiB 跨 run 中位数反转（15.0 vs 4.5）为着色运气，提醒：起始
   沿区内任何单 run 单尺寸中位数都不可单独引用。
