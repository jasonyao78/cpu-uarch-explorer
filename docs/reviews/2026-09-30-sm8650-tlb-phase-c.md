## 2. 读法（解释段，非判定）

- **walk 与延迟在本区间反相关**：walk 密度从 0.19 升到 ~50/1k 的
  同时，cyc/load 与 latency **下降**（22.96→17.66、8.36→6.44）。
  直接原因是中段（1024 页）处于 L1 refill 风暴区（R_0x05 ≈
  1400/1k，Phase B 数据），其成本高于 onset 后的 walk 服务（walk
  处 R_0x05 回落至 ~1100/1k）——translation 各级的成本结构相互抵
  消，**"walk 密度 → 暴露成本"的映射在本协议下连单调性都不成
  立**，这正是 MODEL_UNIDENTIFIABLE 的实质理由（而非仅"没建模
  型"）。
- **data-miss 不混杂 walk 变化**：`0x8144` 在三点全部饱和于
  ~1001/1k（这些 footprint 下每次 load 都 miss L1D），walk 的三
  个量级变化与 data-miss 无共变——"data-miss 共线"这一特定混杂
  在本选点下被经验排除；但 `adjudicate_q3` 的
  data_miss_collinearity_checked 按设计恒为 False（本函数不消费
  G3 数据——G3 五事件组不满足分析器 G0 metric 集契约，见 §3），
  上表对照为执行层登记，不改为该 evidence 字段。
- steps/walk 1.91 → 1.18 → 1.07：walk-active 区 step 短化，与
  MMUTC 缓存中间 descriptor 的机制方向一致（Gate 1 ②登记的派生
  观察的再现）；percyc 与 walk 同步（29.7→1432），walker 活动量
  随 walk 上升。
- **MMUTC 混杂声明保持未分离**：walk 服务时间受 MMUTC（2048 项
  walk 缓存）命中状态影响，任何未来的成本型估计必须显式声明该
  混杂。
