## 从代码和档案得到的事实

`probes/cache-mem/ptr_chase.cpp` 的 A1 路径每进程 20 轮（19 轮统计），每轮访问 512 个 filler 节点和 6–12 个目标节点，进行 3 次 PMU GROUP read、2 次计时调用。256 MiB 是选址空间，未全量触页。目标窗口是 s3−s2，还含计时及用户态边界代码；排除内核计数不等于消除了系统调用对状态的扰动。组件为 `probes/common/perf_window.h`。

`runner/environment/android_state.py` 一次完整 Android 状态采集启动 8 次 adb shell；`runner/engine.py` 每 case 前后各采一次，另有频率及 thermal 辅助读取。旧 L1 档案中，成功 case 的相邻记录间隔中位约 4.190 秒，前置拒测 case 约 1.961 秒；10 份 raw 从 sample0 到 sample9 的落盘跨度中位约 0.325 秒。这说明外围成本值得先检查，不能据此将发热归因给 adb、地址扫描或某个 syscall。数据来源：`data/public/runs/20261008T102132Z-ptr-chase-sm8650-x4-tlb-a1-l1-main/{records,artifacts}.jsonl`，时间是落盘/记录时刻，非阶段 CPU 时间。

`configs/platforms/redmi-k70pro-01.json` 的 charging-thermal profile 请求所有 cpufreq policy 的 performance governor，policy7 max 不一致会拒测。拒测符合现有合同；“所有 TLB 探测都必须运行在这个最高允许频率”不由合同推出。Linux 明确区分频率上限、请求频率和实际时钟：[CPUFreq 文档](https://www.kernel.org/doc/html/latest/admin-guide/pm/cpufreq.html)。

A1 主估计量为每轮 L2 TLB refill，不能称其为纯数据页 walk 数。[Arm Cortex-X4 PMU 定义](https://raw.githubusercontent.com/ARM-software/data/master/pmu/cortex-x4.json)中 0x2d 同时包含指令与数据导致的 L2 TLB refill。探索时应通过负控以及可用的相关事件区分来源；事件计数比 ns 更少直接依赖主频，仍不能先验认定完全不受运行条件影响。

## 科学问题先于框架条件

任何候选实验先回答三件事：不同硬件模型预测什么不同结果？软件是否实际产生该激励？什么混淆因素也会造成同样曲线？若前两项不成立，增加重复次数或门禁不会补足辨识能力。

当前 A1 检验 H1–H4 候选下集中选址、区域隔离和全域组合的冲突曲线，并非直接读出物理 set 编号、ways 或完整 hash。即使唯一候选符合，也只是在已检验候选与控制条件中的支持。所有候选不符时保留未解释结果，不强选一个最接近者。

优先量化一个研究问题：`probes/cache-mem/ptr_chase.cpp` 的 filler 只按收集候选 C 排除目标 set，在被检验模型 M≠C 时未必排除。使用 `probes/common/tlb_set_collect.h` 的合法合成整数 VA 推演，C1/M3 的隔离 scope0、scope1 均选 W=6，但目标硬件 set 可分别包含 0、2 个 filler 页。现有样本尚未构成错误候选也被判 sharp 的反例；这是待量化的混淆因素，不判已证实软件缺陷、不重开既有关闭项。当前输出未保存 filler 映射基址，不能从旧 params 精确重建真实 filler 分布。

## 面向其它 CPU 部件

| 探测项 | 首个有用的实验 | 结论边界 |
|---|---|---|
| TLB/cache | 依赖追逐、页/缓存 footprint 对照、冲突与 scatter 配对 | 先给有效转折、冲突关系与适用条件，再推容量/映射 |
| ALU/FPU/SIMD | 单依赖链测延迟，多条独立链扫并行度与吞吐；固定操作数形态 | 吞吐上限不是物理单元数，需排除前端瓶颈并用混合指令争用交叉验证 |
| ROB/rename/调度窗口 | 长延迟阻塞间插入可控指令，扫填充数并换指令类别 | 拐点先称有效在飞窗口；排除物理寄存器、队列和前端限制后再归因 ROB |
| Load/store/MLP、分支与前端 | 多独立访存链、存储压力、代码 footprint 与分支依赖对照 | 用正交实验区分共享资源，不凭一条曲线命名内部结构 |

| 构造 | 收集参数 | H1/H2/H3/H4 下每 set 最大目标页数 |
|---|---|---|
| A：只改变中间字段 | H1 / regions4 / scope0 | 12 / 1 / 12 / 1 |
| B：只改变高字段 | H1 / regions12 / scope−1 | 12 / 12 / 1 / 1 |
| C：补偿中间字段 | H2 / regions4 / scope0 | 1 / 12 / 1 / 12 |
