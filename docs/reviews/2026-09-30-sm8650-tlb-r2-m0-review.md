# SM8650 TLB r2 M0 批次复审

> 评审编号：REV-TLB-R2-M0-20260930；结论：**要求修改，当前 M0-1/M0-2 不通过本轮验收**。
> r2：`adaac4d777814da481d7140594784d4657696a3c`；比较基线：`a104dbf`，战役基线：`9316853`。
> main 图表：`4b75cf6` 的代码；复审期间 main 更新为 `d1e256c`，新增 TLB pipeline 文档，图表源码未变。
> 范围：M0-1/2/6、任务书 v1.1、相关修订；不修改探针/分析器，不做目标板实验，不替代第二位独立评审。

任务书 v1.1 的科学问题修订方向成立：分布效应先于归因、冲突与非冲突的匹配对照、采样域等价、workload occupancy 与硬件资源数的区分，都比 v1.0 更可识别。M0-2 的方向也成立：缺少无关事件应允许其他估计量继续计算。阻塞在于这个方向尚未形成完整的消费契约。

本轮确认五项 P1：Android 编译回归、不同指标的样本集合静默分离、判据入口守卫不完整、锚点消费者缺失守卫、报告/图表消费者缺失守卫。本机全部现有测试通过不能排除这些缺陷；其中图表问题已使 main 的现有测试在组合后报错。

## 1. 具体发现

### C1 [P1] M0-1 使 Android/Linux 分支无法编译

位置：`probes/cache-mem/ptr_chase.cpp:409`、`:484`；类型定义在 `probes/common/page_policy.h:148`。

`PageBackingClass` 已移入 `probe_common`，两处 Linux 分支仍写 `const PageBackingClass`。本机 macOS 不编译这两个分支，18 项 CTest 全通过。

用本机已安装的 Android NDK 27.2、`aarch64-linux-android29-clang++`，打开 `CPU_UARCH_HAVE_LINUX_PERF=1` 作真实目标语法检查：

| 源码 | 退出码 | 结果 |
|---|---:|---|
| a104dbf 原文件 | 0 | 通过 |
| 当前 r2 | 1 | 两处 `unknown type name 'PageBackingClass'` |
| 临时副本，仅补两处 `probe_common::` | 0 | 通过 |

这是新引入的确定性编译缺陷，不只是运行覆盖不足。修复这两处后，还需正常目标构建与 Linux/Android VMA/页审计验证；语法检查不证明链接或运行行为。

### C2 [P1] 汇总静默删除 None，跨指标不再共享样本集合

位置：`analysis/sm8650_tlb.py:795–825`，重点为 `:817–825`。

同组同时出现完整记录与缺指标记录时，代码对每个字段分别过滤 None，再计算统计量。`metric_contract.missing` 虽记录缺项，但 group 的对应统计对象仍可能非 None，现有判据与图表也不消费该清单。

合成软件输入：同键两条记录各两样本。完整记录 latency=[100,110]、cycles/load=[100,110]；缺 cycles 的记录 latency=[1,2]。结果为：

| 报告内容 | 使用样本数 | 中位数 |
|---|---:|---:|
| group 总样本数 | 4 | — |
| latency | 4 | 51 |
| cycles/load | 2 | 105 |

main 图表照常输出 cycles 点 `(512,105)`，没有披露其只用了两样本。由这些不同集合构造关联、配对或跨指标解释，会引入选择偏差。以上数字仅用于复现软件缺陷，不是硬件测量。

应冻结每个估计量的联合可用样本集合，记录实际样本数与排除原因；缺必要字段时不可晋升该估计量。只缺无关字段不能全组封禁。若允许单指标的部分覆盖描述，必须显式标明 coverage，不能冒充同一组完整配对数据。

### C3 [P1] 两个已加守卫的判据仍有绕过路径

位置：`analysis/sm8650_tlb.py:613–617`、`:669–674`、`:705–714`。

`adjudicate_knee` 在调用受保护的 `detect_knee_candidates` 前，先计算 32 页 floor 的 `refill >= threshold`。refill=None 时，这里直接抛 TypeError，根本到不了 INCOMPUTABLE 守卫。新增测试只调用了候选函数，未经过公开裁定入口。

walk-onset 的守卫只检查行中位数。完整与缺 walk 记录混合时，C2 让 group 中位数非 None，但 `walk_samples` 中仍含 None；`_walk_point_qualifies` 的 `value > floor` 再次抛 TypeError。

应在公开裁定入口、任何先行算术/比较之前校验全部实际依赖；walk 判据必须同时约束逐样本集合与其有效样本数。回归需覆盖完整缺失和部分覆盖两种输入。

### C4 [P1] 锚点复用了新解析器，却没有声明更严格的消费要求

位置：`analysis/sm8650_tlb.py:1606–1627`、`:1638–1663`、`:1766`。

`_anchor_groups` **已经调用同一个 `analyze_records`**，没有另写一份精确 metric 集合检查；这是对关注点 5 的直接回答。但它只检查 `{512,3072}` 的组形。解析器放行缺项后，锚点的 band、walk count、baseline 与 evidence 消费者仍假定统计对象/样本值全为数值。

合成完整 before/main/after 块，单独移除 before 的事件：

| 移除事件 | 锚点裁定 |
|---|---|
| cycles | TypeError |
| l1d_tlb_refill | TypeError |
| dtlb_walk | TypeError |
| mem_access_rd | ANCHORS_OK |

最后一行是合理行为：锚点判据不依赖 mem_rd，不能把 G0 的全部事件再硬编码为锚点必需集合。正确做法是共享解析/校验实现、分别声明锚点与主体估计量的依赖。必要锚点事件缺失必须显式不可判定，并阻止主体结论晋升。

正向验证：只移除主体的四个 PMU 事件之一，完整锚点仍能返回 ANCHORS_OK。锚点/主体解耦这一部分已实现；它不意味着主体所有下游路径可用。

### C5 [P1] Markdown 与 main 图表没有接受新的 nullable 统计对象

位置：r2 `analysis/sm8650_tlb.py:1932–1948`；main `analysis/tlb_figures.py:83`、`:114–115`、`:385`。

`_fmt(None)` 无法解决 group 字段整体为 None：报告器先执行 `stats['median']`，随后才调用 `_fmt`。四种 PMU 缺失都能让汇总报告 TypeError；逐样本输出还直接用浮点格式化 None。`bimodal=None` 则被布尔分支显示为 `no`，把不可计算误写成未发现双峰。

main 的 `seed_medians` 同样直接访问 `group[field]['median']`。CLI 不捕获 TypeError。把 main 的 19 项图表测试接到 r2 分析器，结果 **18 通过、1 error**：`TestCli.test_missing_metric_fails` 原期望受控退出码 1，现在出现 TypeError。这是已有负例测试明确暴露的跨分支兼容性回归。

新增 `metric_contract` 字段本身是安全的附加键；失败来自统计字段可为 None 的类型变化。应显示 n/a 与具体原因、披露 coverage，图表对必要字段给命名失败或显式省略的审计记录；不能用 0 替代。比较级 cohort 的统计路径也需服从同一契约。

### C6 [P2] 超集字段只保留名字，OI-13 的交付口径需收紧

位置：`analysis/sm8650_tlb.py:430–434`、`:473–474`、`:800–814`；`docs/open-items.md:159–164`。

extra 指标不进入 `indexed`，也不进入 sample；AnalysisResult 仅保留 extra 名字。原始 records.jsonl 中的观测仍在，但不能说 AnalysisResult 保留了 extra 的 per-observation 编码、窗口、页审计或数值，也没有派生该事件字段。

OI-13 的原跟踪描述包含“放行并派生对应字段”，当前实现只做到放行；任务书现在允许“按名忽略”，应明确缩小交付范围与存档位置。`adjudicate_q3` 的 docstring 仍说 G3 不符合入口集合契约，也应同步。

因此 **OI-13 不应宣称关闭**：超集解析、主体/锚点解耦部分完成；必要字段的消费降级和额外事件的具体处理仍未闭环。r2 的 open-items 状态仍是“待办”，与提交标题的 close 存在口径差异。

### C7 [P2] B1/B2 与 offset 的冻结缺口仍在

位置：任务书 v1.1 `:26`、`:33–38`、`:109–120`。

B1/B2 定型应依赖独立 pilot 对协议能力/可识别性的验证，不能观察哪个 H 或哪个方案曲线更漂亮后再选。建议先明确默认主估计量、备用切换条件、预算、决策时点、pilot 与正式验证的隔离，并在 Phase B 正式采样前冻结。B2 特别依赖 victim 二值分类器及误判校准；B1 也必须证明其目标访问实际暴露 L2 查找，而非仅驻留 L1。

Q-A 的 offset 应作为**节点地址策略**，与页集合和访问次序分离：`node[i]=base+page_id[i]*page_size+offset(i)`，按 permutation 建 `node[i]→node[next(i)]`。不能把 stride 从 4096 改成 4160 来模拟，它会同时改变页集合和几何。需冻结 offset 是页槽/页 ID 的函数还是访问位置函数；跨访问 seed 对照时，同一页的 offset 应保持一致。

至少记录 requested/realized offset policy、distinct pages、VA span、cache-line footprint，校验对齐、不跨页、每页恰一节点、无重复地址。实现归属为 M0-4/Phase A，当前批次可登记待办，正式测量前必须完成。

### 3.3 GuardedMap 的等价性边界

正常输入的页尺寸取整、两端 guard、mprotect 与调用方 munmap 责任，从源码看与原来相当；smaps 归属算法主要变化是命名空间/三元表达式改写。这个判断属于代码审查证据。

`GuardedMap` 是 POD，不是 RAII；无析构、复制可用，资源仍由调用方手动释放。M0-1 任务书要求的 RAII、合法地址池、timer、CPU/MIDR 并未全部落地，应称“页策略提取子项”，不要按整个 M0-1 完成验收。

错误路径也不能声称逐字行为等价：mprotect 失败后 helper 先 munmap 再返回，调用方统一打印 `mmap guarded buffer`，原来打印 `mprotect guarded buffer`；errno 没有显式保存。以上主要影响诊断，但应写进等价性例外。

建议证据分级：源码审查、macOS 构建/执行、目标交叉构建、Linux 运行、Android 目标运行分别列明。当前已取得前两项，第三项失败，后两项未执行。
