## 0. 范围决策：A3 后置

RPA-01 的第三个阻塞是**协议级**的：prime+probe 的 W 窗口协议每轮只访问 W 个节点，N-set 建出的链从未被测量——修上限/扩 filler 都不能构成"translation reach"的测量。正确的 A3 需要：全链遍历模式（每轮 probe 走完整工作集 = 真 capacity-curve 协议）、独立的 filler/L1 暴露机制、随长度重校准的计数分母。这值得单独立项而非塞进本轮。

**登记（open-items）**：A3-整体 translation reach——触发条件 = A1 判出 H* 后；交付物清单 = 全链遍历探针模式设计 + 可执行性推演（地址遍历/filler 预算/分母标定）+ 每计划点 plan 预览通过 + 访问追踪金样。

## 1. RPA-02 审计计数修复（小）

**探针**：`per_region_counts` 从"每次收集追加"改为**固定 K 槽位按 region ID 累加**（K = regions 数；scope 隔离时槽位不变、仅对应槽非零）。目标链与 T2 各用独立审计向量。

**输出**：`set_target_region_nodes=k1,k2,k3,k4` + `set_t2_region_nodes=...`（有 T2 时）；`set_active_regions` = 目标链向量非零槽位数。新增不变量校验（探针侧，fail-closed）：节点总和 == window×max(nsets,1)；scope≥0 时仅 slot[scope] 非零。

**测试**：生产函数提取金样——N=4/96/256、T2、单区域隔离、跨界布局，断言槽位数恒 K、active=真实区域数、总和不变量。（本轮教训的对症药：审计测试必须覆盖 N-set/T2 消费场景。）

## 2. RPA-03 realized 逐次闭环（中）

**adapter**：`parse_realized` 全面防御——所有 int 解析包成 ParseError；`region_nodes` 逐 token 校验（非负整数，非法 token **拒绝而非丢弃**）；维数校验（len == regions 槽位数）；总和/scope 一致性校验。任何校验失败 → ParseError。

**engine**：每次进程解析成功后即取 `realized_i` 绑定 sample_index；聚合时比较全部 realized 的规范形：
- 全部一致 → `record.probe.realized` = 公共值（现状语义保持）；
- 不一致 → `record.probe.realized` 改为**逐样本列表** `[{sample_index, raw_ref, realized}]` + `record.probe.domain_consistent=false`（**record 仍 ok**——数据不丢，命名状态交判据入口处置）。
- parse_realized 抛 ParseError → 走既有 first_failure 路径（空 metrics + 结构化 failure）——评审复现的 ValueError 逃逸随防御修复消除。

**判据入口**：A1 门从 `domain_consistent==false` 的 record 直接拒绝（命名理由 mixed-domain），不静默采纳首样本值。

## 3. RPA-04 完整残差身份（关键设计）

**导出**：`group.identity` 增加 `residual_digest`：对 params 做递归规范形（PA-07 同款）后取 sha256-12；**digest 为空集时 = None**。

**排除集（digest 不覆盖的"协议反射参数"）**——这是旧数据兼容的命门，逐名论证：

| 排除名 | 理由 |
|---|---|
| buffer_kb, seed | 已是分组键维度 |
| loads, stride | 语义完全反射进 ring_passes 键维度 |
| base_pages, thp, hugepage | 页面策略请求旗标——其实际 backing 已由 page_policy_actual 键维度承载（campaign 合约）；**归档记录普遍带这些旗标，不排除会全员触发守卫、历史图表全拒**（已核实锚点/THP 配置记录 params 含 base_pages=1） |
| page_policy_actual | 键维度本身 |

**不在排除集的一切**（warmup、warmup_passes、loads_per_slot、min_loads、chains、set_*、任何未来新维度、descriptor 对象）→ 进 digest。

**验证评审反例**：loads_per_slot=8/16、warmup_passes=2/4 的 latency 记录 → digest 不同 → identity 不同 → 下游拒绝 ✅。旧 51 runs：所有 params 落排除集 → digest=None → 守卫不触发、重放逐字一致 ✅（已推演，实现后跑重放实证）。

**下游守卫改法**（analyzer cohort + main 图表 seed_medians）：拒绝条件 = 任一**声明维度**非 None **或 residual_digest 非 None**。不再扩白名单——新维度自动进 digest 自动被拒，ROB/ALU/FPU 的新条件不需要再改守卫。

**风险与对策**：若未来某 legacy 兼容需求要求老记录带新维度（如重跑旧配置加了新旗标），digest 会非空 → 图表拒——这是**命名拒绝而非数据丢失**，符合契约语义；真需要消费时按 PA-01 模式加"显式分系列"支持。

## 4. RPA-05 A1 v2 设计（任务书修订稿预览）

**scope 特定审计门**：expected_active = (scope<0 ? regions : 1)；门按 record 的**请求 scope + realized** 判定，全域/隔离用各自阈值——修掉"隔离 case 被全域硬门误杀"。

**真实 VA 进预测表**：探针输出 `set_region_vpn_hi=k0,k1,k2,k3`（各区域基址 VA[35:28]，随全量自描述）。分析侧用**实际值**计算候选冲突分区；若某 region 内部跨 vpn_hi 边界（单 64MiB 区域跨 256MiB 不可能——64MiB < 256MiB，恒不跨！评审的反例成立条件是 region 尺寸 ≥256MiB 或基址未对齐；64MiB 区域基址任意时 vpn_hi 仍单一，因为 64MiB < 256MiB 窗口——**实现时验证此推理**，若成立则 region 内 c 恒定的担忧消除，只需记录实际 vpn_hi 供分区计算）。

**分层矩阵**（预算机器核算后冻结）：
- L1 主判定：H(4)×scope(3)×W[6,8,10,12] = 48 cases @seed42；
