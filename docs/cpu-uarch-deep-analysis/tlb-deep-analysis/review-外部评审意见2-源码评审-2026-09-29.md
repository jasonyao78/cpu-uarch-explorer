评审了 `probes/` 下的两份 C 源码和 README。**它们目前可以作为探测思路草稿，但输出还不能用于判定 L1 容量、L2 索引函数或并行 walk 深度。**以下只评估探测原理与代码证据链。

### 必须先修正

1. **L2 探针被 L1 dTLB 遮住。** [l2_set_probe.c](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/l2_set_probe.c:134)稳定重访最多 16 个目标页，而 X4 的 L1 dTLB 有 96 条。预热后目标访问可全部在 L1 命中，`L2D_TLB_REFILL≈0` 不能证明候选页不冲突。需要在目标访问之间受控地驱逐 L1 翻译，并以 `L1D_TLB_REFILL`、`L2D_TLB` 确认请求确实到达 L2；再比较同组候选与非同组对照。[X4 TRM 的容量及事件定义](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)

2. **L2 计数窗口无法剔除初始化和首轮。** 探针依赖进程外的 `perf stat`，它会计入建链时的首次触页；[测量循环](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/l2_set_probe.c:144)没有分轮事件记录。因此 [README 的“剔除首轮后看跳变”](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/README.md:61)目前做不到。应在预热后才开启计数，或分别输出预热与稳态的计数窗口。

3. **同组地址的“最终 VA 校验”实际仍在校验相对页号。** [生成器](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/l2_set_probe.c:44)对 `v` 计算索引，再对同一个 `v` 复核，没有计算 `((uintptr_t)base + v*pagesz) >> 12`。ASLR 基址会使 XOR 假设下的实际 set 改变；`gen` 与 `run` 又是不同进程，README 所称“复用生成器保证同一地址集合”不成立。前 16 个匹配地址也不足以区分 H1/H3、H2/H4，必须让样本跨越各假设使用的高位区间。

4. **容量探针的 stride 模式越界，random 模式未随机化页集合。** [地址生成](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:75)把 stride 页号设为 `i×256`，但[只分配 `N` 页](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:156)；`N=96` 时第二个访问页号 256 已超出映射。random 只重排 `0…N−1`，与连续组使用相同 VA 集合，不能验证报告要求的“三种地址分布”。

5. **容量探针的预热可能被优化掉；本机已观察到这一结果。** [预热循环](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:181)的 `p` 未被使用，读取也不是 volatile。本机 Clang `-O2` 生成的优化后 IR 中，这段预热 load 已消失；后面的编译屏障救不回已删除的循环。可让预热使用与测量相同的受约束追逐函数，并把结果写入真正的 volatile sink。现有 `volatile char *g_sink` 修饰的是**所指字符**，不是指针变量自身。

6. **PMU 打开失败会被报告成有效的 0。** [perf_read()](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:104)在 `fd<0` 时直接返回初始值 0，而输出只把 `UINT64_MAX` 视为不可用。权限不足或事件不受支持时，结果会伪装为“零 refill”。应将打开失败明确报错并终止该配置；还需记录 `time_enabled/time_running`，防止复用计数器时把未缩放计数当成完整窗口。

### 会误导微架构解释的问题

- [快速／慢速模式](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:192)仍是一条串行依赖链，不能制造多个同时在途的 data-side walk，故两组差异不是 walk 队列深度的指纹。`ns_per_load` 在 slow 模式还把轮间 busy-wait 算入分子。应改用多条独立 miss 流探测并行度；逐轮时延若要剔除首轮，也必须输出原始逐轮数据，现有代码只输出汇总百分位。

- [匿名连续映射](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:156)并未证明每个被访问的 4 KB 页都占用独立 TLB 条目。报告要求控制大页和合组，探针却没有检查实际映射粒度；X4 还默认启用可单独控制的硬件页聚合。容量拐点必须在确认这些状态后解释。[X4 TRM 控制寄存器定义](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)

- [绑核失败](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:149)只打印错误而继续运行。在 X4/A720/A520 异构平台上，这会使“X4 RAW 事件”与容量归属失去前提，应让该次实验失败。PMU 窗口也覆盖逐轮计时和 slow busy-wait；解释小计数差异时需要空循环对照。

### README 与源码的一致性

[README](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/README.md:1)目前只列出两份**数据侧**探针；报告 §5.6 的 iTLB 执行页探针尚无对应源码，因此该部分无法做源码评审。README 的 L2 示例使用 `perf stat`，后文又要求 Android 使用 `simpleperf`；[容量探针注释](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:27)使用 `taskset -c 7`，与 README 所写的目标平台语法相冲突。更关键的是 README 将“way 跳变=8”写成可直接执行的判据，但当前代码既未强制 L1 miss，也未取得稳态分轮计数。

**验证范围：**两份源码经本机 Clang `-O2 -fsyntax-only` 检查通过，仅有 GNU `asm` 的 pedantic 扩展警告；我另检查了容量探针的优化后 IR，确认预热读取消失。未在 Cortex-X4 目标机运行，因此没有宣称任何容量或 PMU 实测值。
