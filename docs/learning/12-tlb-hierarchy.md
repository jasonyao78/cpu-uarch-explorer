# 12 · TLB 层次：翻译也是一层 cache

> 费曼段：一句话——**TLB 是"翻译结果"的 cache：把每次访存附带 4 次查页表，压到接近零。**

## 概念

**要解决的问题——"翻译墙"**：CPU 发出的是虚拟地址（VA），cache 和内存要的是物理地址（PA），映射关系存在内存里的 4 级页表中。如果每次 load/store 都逐级查页表，一次翻译 = **4 次串行依赖的内存访问**，每次几十上百周期——比 L2/L3 访存本身还慢一个数量级。乱序窗口开再大、load 带宽做再宽，翻译供给跟不上，流水线照样挨饿。

**TLB 的做法**：把最近用过的 VA→PA 翻译缓存起来。它和数据 cache 完全同构——有命中/缺失、容量、相联度、替换策略——只是缓存的不是数据而是翻译：查找键是 VPN（虚拟页号）+ ASID 上下文标记，查找值是 PPN + 权限属性位。

**为什么分层**：单级 TLB 面临与单级 cache 相同的矛盾——要大就不能快。L1 TLB 必须约 1 个周期命中（否则卡在 load-to-use 关键路径上），所以只能**小容量 + 全相联**（全并行查找，无 set 冲突）；L2 TLB 退到 miss 路径上，就可以做大，代价是引入 **set 相联**——于是"VPN 映射到哪个 set"成为一个真实的硬件问题（哈希函数，不公开）。

**X4 地面真值（TRM Table 5-1/9-32，不用测）**：

| 级 | 结构 | 覆盖（4K 页） | 备注 |
|---|---|---|---|
| L1 I-TLB | 48 条 · 全相联 | 192 KiB | |
| L1 D-TLB | 96 条 · 全相联 | 384 KiB | 1 周期命中契约 |
| L2 TLB | 2048 条 · 8 way × 256 set | 8 MiB | I/D 共享；还混存 walk 中间级描述符 |
| + MMUTC | 未公开 | — | iTLB 的 miss 回填源（d 侧则由 L2 直接回填，I/D 不对称） |

**粒度杠杆**：同样 2048 条 L2 条目，4K 页覆盖 8 MiB，2M 大页覆盖 4 GiB——512 倍差距。粒度是覆盖范围上最便宜的放大器，也是测量时最大的软件侧混淆变量（本机 THP=`[always]`，见"坑"4）。

**TRM 不告诉你的**（这才是要测的）：替换策略、VPN→set 哈希、8 way 实际"好用"几个、walk 器在负载下的行为、HPA（硬件页聚合）的实际状态。结构查手册，**行为只能测**。

## 六个坑（混淆变量，全部在实战里踩过或防过）

1. **以延迟测容量在 L2 层必然失真**：walk 代价不是常数——页表本身走数据 cache，中间级命中时 1 次内存读、全 miss 时 4 次。延迟通道被系统性污染（lmbench 式拐点法的通病）——这是本项目 L2 层**改用 PMU 计数**的核心理由。
2. **事件率 ≠ 概率**：refill/load 不是 [0,1] 的 miss 率（战役实测 R_0x05 >1000/1k——重填可以比访问多）。事件计数只能当"行为指标"，不能当概率读。
3. **条目纯度**：L2 的 256 个 set 里，最终翻译和 walk 中间级描述符**混住**。所以"第 9 页才溢出 8 way"的教科书预期不成立——实测 W=8 就跳（见测量栏），判据必须按"总竞争条目数"写。
4. **粒度混杂**：THP=[always] 下，你以为的"一个 4K 页"可能被 2M 大页背书——每条翻译覆盖的范围变了，页数账全错。防守：smaps 端点审计（AnonHugePages=0）当硬门。
5. **I/D 不对称**：dTLB miss 由 L2 回填，iTLB miss 经 MMUTC 回填——两侧事件语义不能直接互推（本期 I 侧不做，任务书非目标）。
6. **cache↔TLB 互相污染**：walk 读页表就是普通 data 读，**计入 cache PMU 事件**——TLB 实验和 cache 实验在计数层面互相可见，设计上必须隔离。

## 测量

**容量侧（第一战役，证据级，终审 2026-09-28）**——方法：ptr_chase 长链延迟 + PMU 同窗，按页数扫描：

| 问 | 终态 | 读法 |
|---|---|---|
| Q1：L1 refill 转折点 | **INTERVAL_IDENTIFIED [120, 1024] 页**（480 KiB–4 MiB） | L1 只有 96 条，转折却是**宽带**而非墙：全相联 + 随机环访问下 refill 概率随 N 平滑上升，且 L2 的 2048 条把每次 L1 miss 变得很便宜——墙被抹成了带。所以只主张区间，**不主张物理项数**（任务书非目标） |
| Q2a：walk onset | **INTERVAL_IDENTIFIED [2560, 3072] 页**（10–12 MiB） | 下沿恰在 L2 覆盖（2048 页=8 MiB）之上 1.25–1.5 倍——与 TRM 结构自洽 |
| Q3：walk 暴露成本 | **MODEL_UNIDENTIFIABLE** | 实测 walk 与延迟**反相关**，单调性不成立——诚实的"这台仪器看不见它" |
| Q4：mixed-THP | 受限一致（lat −12.4% / R_0x05 −82%） | 方向一致但只够比较级 |

**set/way 侧（r2 战役，进行中）**——方法：prime+probe（filler 驱逐 L1）+ 短窗 GROUP 计数；正控 = W 页集中同 set，负控 = 同样 W 页打散多 set。

- **B1 自冲突曲线**（2026-10-07 pilot，CALIBRATION/PILOT 级，19 有效轮 × 10 重复，H1/target set 7）：L1 refill ≈ W+2、L2 lookup ≈ W+2（+2 恰是空窗底噪）——协议自洽；**L2 refill：W=1..6 ≈ 0（0~0.5），W=8 跳到 5.95，W=12 达 12.0**——跳变提前于教科书点（坑 3）。负控两个尺度全 0.0，空窗 L2r=0.0。
- **0x2f（L2 lookup）资格之路**：战役1 = SEMANTICS_UNVERIFIED（不敢用）→ 2026-10-01 冒烟复验行为正常（w+常数线性、方向不反降、跨 set 一致、可复现，备忘录级）→ 拍板升级三事件门控 → pilot 中正式服役。**一个事件从"不敢信"到"当判据"的完整资格化流程**。
- **计时降级**：短窗 probe_ns 实测非单调，门控全靠事件计数，计时只作上界辅证（01/02 页方法论在 TLB 域的重演）。

## 费曼自测

1. L1 TLB 为什么是小容量全相联？（1 周期命中契约 → 全并行查找；大容量做不进关键路径；全相联还免掉了 set 冲突分析）
2. L1 dTLB 96 条，为什么实测转折是 [120,1024] 的宽带而不是 96 处的一堵墙？（全相联随机访问下 refill 概率平滑上升 + L2 缓冲 miss 代价 → 墙被抹成带）
3. 为什么 L2 层不能用以延迟测容量？（walk 代价是 1~4 次内存读的随机变量：页表走数据 cache，中间级命中与否决定代价）
4. 同 set 第 9 页才溢出 8 way，为什么实测 W=8 就跳？（set 里还住着 walk 中间级描述符等竞争者；总竞争条目数 ≠ W）
