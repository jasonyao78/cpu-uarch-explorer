## 评审结论

报告引用的 Cortex-X4 TLB 基本参数——L1 iTLB 48 条、dTLB 96 条、共享 L2 TLB 2048 条且为 8 路——与 [Cortex-X4 r0p3 TRM Table 5-1](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)一致。但**现有探测原理和代码还不能支撑 L2 索引函数或并行 walk 深度的结论**。建议先修正以下问题，再把预期曲线用作判据。本次只做静态评审和资料核对，未在 SM8650 上测量，也未修改文件。

### 阻断探测结论的问题

1. **L2 同组实验实际测不到稳态 L2 冲突。** [§5.5](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:537)要求用 1–16 个目标页寻找 8 路跳变；[探针循环](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/l2_set_probe.c:134)也只反复访问这些页。16 页全部装得进 96 条 L1 dTLB，稳定后不会再查 L2。外层 `perf stat` 还包含建链和首轮，代码没有可剔除首轮的分段计数。应在**每次目标访问前有控制地制造 L1 miss**，同时用 `L1D_TLB_REFILL`、`L2D_TLB` 验证目标确实到达 L2，并设置同等干扰的对照组。即使确认 8 路，9 个冲突页也不保证“每页每轮必 miss”：替换策略与 walk 条目会改变曲线。[TRM 的事件定义](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)区分了 L1 回填、L2 访问和 L2 回填。

2. **“快速／慢速重访”不能测并行 walk 数。** [§3.3](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:275)与[代码](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:192)采用单条指针依赖链：下一次 load 的地址要等上一次返回。因此该链本身不能同时发出多个独立的 data-side walk；轮间等待也不会让已经完成的上一轮 walk“再完成一次”。要探测并行度，应构造多个**地址互不依赖**、确实产生 L2 TLB miss 的 load，逐步增加并发数，结合延迟及 `DTLB_WALK_PERCYC` 判断饱和点。TRM 将该事件定义为每周期进行中的 walk 事件数之和。[TRM PMU 事件表](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)

3. **候选同组地址没有按最终 VA 校验。** [§5.5](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:542)写作 `VPN[19:12]`，但若 `VPN=VA>>12`，代码的低 8 位实际是 `VPN[7:0]=VA[19:12]`。[生成器](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/l2_set_probe.c:44)又对 **mmap 内的相对页号**计算哈希，未把 `base` 加入复核。以 H2 为例，基址页号为 1 时，相对页号 `0x101` 和 `0x202` 都算出 set 0，最终 VA 对应的 set 却分别为 3 和 1。此外，取前 16 个候选页时，高字段可能始终不变，H1/H3、H2/H4 会在这组样本上不可区分。应统一位编号，按最终 VA 生成与验证地址，并跨越所检验的高位区间取样。

4. **L1 三分布对照尚未构成三种地址分布。** [容量探针](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/probes/tlb_capacity_probe.c:75)的 random 模式只打乱同一批连续页的*访问顺序*，没有改变页号集合；stride 模式分配 `N` 页，却访问第 `i×256` 页，`N=96` 时第二个页号 256 已越界。因而 [§5.4 的全相联验证](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:509)目前既无法按设计执行，也不能由 random 组证明“地址分布无影响”。

### 需要纠正的体系结构判断

- [§2.3](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:144)把 `64 KB ÷ 4 way` 算成 **4 KB/way**；正确值是 **16 KB/way，即每路 256 条 64 B cache line**。TRM 的 L1 cache RAM 定位字段也列出 VA `[13:6]`，不能据“索引全在 4 KB 页内”证明无别名。TRM 确实称其 *VIPT behaving as PIPT*，但报告给出的算术解释不成立；具体如何实现这一行为应与公开结构事实分开写。[TRM L1 cache 与 RAMINDEX 表](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)

- [§1.4](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:86)称 40 位 PA 使 1 GB 块“无意义”，与同一 TRM 明列的 **L2 TLB 1 GB 块支持**矛盾。40 位 PA 仍有 `2^(40−30)=1024` 个对齐的 1 GB 物理区间。L1 dTLB 所列最大粒度 512 MB，是该级 TLB 的支持范围，不能归因于 PA 宽度。[TRM Table 5-1](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)、[Arm 地址翻译粒度说明](https://documentation-service.arm.com/static/6489c105153eb247a5450414)

- [§5.1](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:433)把“打乱访问顺序”当作避免合组的主要控制手段。合组取决于**映射及硬件状态**，不是访问顺序；TRM 还列出默认启用的 `HPA_L1_DIS`／`HPA_DIS` 所控制的硬件页聚合，与 contiguous hint 是不同控制项。因此“96 页／2048 页必在标称容量处出现干净拐点”应降为待验证假设，先确认实际页粒度与聚合状态。[TRM 控制寄存器定义](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)、[Linux arm64 contiguous bit 说明](https://docs.kernel.org/arch/arm64/hugetlbpage.html)

- [§5.6](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:564)称“每页一次取指”，但从页首执行整页 NOP、页尾 RET，会实际执行约一页指令；48 页代码量已达 192 KB，超过 X4 的 64 KB L1 I-cache，还引入取指预取与返回预测效应。建议每页使用长度相同的极短跳板，改变页内偏移作对照，并同时记录 I-cache、分支与 iTLB 事件。[TRM L1 I-cache 参数](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)

- [§2.7](/Users/michaelyao/workspace/cpu-uarch-explorer/docs/tlb-deep-analysis/TLB微架构深度分析报告.md:197)由“iTLB 从 MMUTC 回填”进一步断定 **MMUTC 就是独立 page-walk cache**，证据不足。TRM 确认 MMUTC 的存在和回填来源，也确认 L2 缓存中间描述符，但未在所引条目中给出 MMUTC 的条目内容。`*_STEP` 是 walk step 事件；其平均值不能不经对照就直接换算为 walk-cache 命中率。[TRM MMU 与 PMU 章节](https://documentation-service.arm.com/static/67804d2f3f2a9a07789e1cf0)

原理级地址生成至少应先改为按**最终虚拟地址**计算；这段只修正候选构造，尚不构成上面第 1 项所需的 L2 测量协议：

```c
static uint8_t h2_set(uintptr_t va) {
    uint64_t vpn = va >> 12;             // VPN[7:0] = VA[19:12]
    return (uint8_t)((vpn ^ (vpn >> 8)) & 0xff);
}

for (size_t i = 0; i < region_pages && found < wanted; ++i) {
    uintptr_t va = (uintptr_t)base + i * 4096;
    if (h2_set(va) == target_set)
        targets[found++] = va;
}
```
